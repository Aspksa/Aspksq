# TRACKTOR — локальная версия для одного пользователя

Командный центр и интерактивная карта «Второй мозг», реконструированные по видео.
Данные хранятся в SQLite на вашем компьютере. Для локальной работы регистрация, Supabase, интернет и отдельная установка СУБД не нужны. Для необязательного подключения моделей Cloud.ru нужен интернет и ваш API-ключ.

## Запуск на Windows 10/11

1. Распакуйте проект **целиком** в папку, в которую у вас есть право записи.
2. Дважды нажмите **Aspksa.bat**. Сайт откроется автоматически.
3. Оставьте окно сервера открытым, пока работаете. Чтобы остановить сервер, нажмите в нём **Ctrl+C**.

**Python вручную устанавливать не требуется.** Загрузчик проверяет найденный Python версии 3.9+ вместе с модулем SQLite. Если подходящего Python нет, скачивает последнюю опубликованную версию Python 3.13 с **python.org**, проверяет действительность цифровой подписи Python Software Foundation и устанавливает его для текущего пользователя. Права администратора и изменение системного PATH не требуются. Для первоначального скачивания нужен интернет. Установка сохраняется в `%LOCALAPPDATA%\Aspksa\Python313` и используется при следующих запусках.

BAT содержит только ASCII-команды; вся логика находится в `Start-Tracktor.ps1` с UTF-8 BOM для Windows PowerShell 5.1. Пути передаются отдельными аргументами без `Invoke-Expression`, а операции с файлами используют буквальные пути. Поддерживаются кириллица, пробелы, скобки, квадратные скобки, апостроф, `&`, `!` и `%` в имени папки. Не запускайте BAT из окна просмотра ZIP: сначала извлеките все файлы.

### Адрес, порты и повторный запуск

- По умолчанию сервер использует `http://127.0.0.1:4173/`.
- Если порт занят или недоступен, операционная система выделяет другой свободный порт. Браузер открывает **фактический адрес**, показанный в окне сервера.
- При повторном нажатии BAT открывается уже работающий сайт. Второй сервер для той же базы не запускается; чужие процессы не завершаются.
- Блокировка базы автоматически снимается операционной системой после остановки процесса. Оставшийся служебный файл не мешает следующему запуску.
- Браузер открывается после проверки готовности именно этого экземпляра приложения и его базы.

BAT вызывает Windows PowerShell с параметром выполнения для одного процесса. Системная политика PowerShell не изменяется. Если запуск запрещён политикой организации, появится ошибка; такие ограничения автоматически не обходятся.

### Если запуск не удался

Окно ошибки остаётся открытым. Журнал подготовки и код завершения сервера — `data/launcher.log`. Если нет доступа к python.org, установите Python 3.9+ вручную с https://www.python.org/downloads/ и повторите запуск. Если папка защищена от записи, перенесите **весь проект вместе с data** в свою обычную папку.

На Linux/macOS или из терминала:

```bash
python3 server.py --open-browser
```

На Windows вместо `python3` можно использовать `py -3`. Для другого предпочтительного порта: `py -3 server.py --port 4174 --open-browser`. Путь к базе определяется относительно папки проекта, независимо от текущей папки терминала.

Открывать `index.html` напрямую или использовать `python -m http.server` для работы с базой не нужно.

## Рабочий стол, «Документы», другой диск и флешка

Папку приложения можно размещать на рабочем столе, в «Документах», во вложенной папке, на другом локальном диске или на флешке с NTFS, FAT32 либо exFAT. Запускайте `Aspksa.bat` внутри этой папки. Рабочая папка терминала и буква диска не определяют расположение данных: загрузчик передаёт полный путь к своей базе в `data`.

Для переноса:

1. Остановите сервер (`Ctrl+C` в его окне).
2. Переместите или скопируйте **всю папку приложения вместе с data**.
3. Запустите BAT из нового расположения. Настройки и навыки останутся в той же базе; старая буква диска и служебный файл предыдущего запуска этому не мешают.

На другом компьютере проверка/установка Python выполняется заново, если там ещё нет подходящей версии. Сам Python устанавливается для пользователя этого компьютера, а база остаётся рядом с приложением на выбранном диске/флешке.

Перед запуском проверяются создание, запись, переименование и удаление служебного файла в `data`, а также атрибут «Только чтение» существующей базы. Если флешка защищена от записи или Windows блокирует папку, выводится понятная ошибка. База не переносится автоматически в другую папку.

Если носитель отключится во время работы, запросы к базе сообщат об ошибке и не создадут вместо пропавшего файла пустую базу. Перед извлечением флешки обязательно остановите сервер и используйте безопасное извлечение Windows.

Windows CI переносит одну базу с тестовым навыком между рабочим столом, «Документами» и вложенной папкой; затем запускает её на **новых одноразовых виртуальных томах FAT32/exFAT**, меняет букву диска и папку и проверяет сохранность данных и повторный запуск. Физическая флешка в CI не используется. Виртуальные тестовые диски создаются только тестовым скриптом в одноразовом окружении, не загрузчиком приложения.

## Где данные

При первом запуске автоматически создаётся **data/tracktor.sqlite3** с таблицами клиентов, проектов, навыков, процессов, задач, уведомлений и настроек. Один пользователь, без паролей и аккаунтов. Сервер принимает подключения только с этого компьютера через `127.0.0.1`.

Существующие демонстрационные клиенты (19), проекты (20) и процессы (6) копируются в новую базу один раз из `seed-data.json`. Повторный запуск не перезаписывает данные и не добавляет дубликаты. Это исходные примеры из видеозаписи, а не ваши реальные клиенты.

Из интерфейса можно добавлять собственные навыки и сохранять настройки карты. Кнопка **Обновить** перечитывает данные из базы. Редактор клиентов/проектов/процессов в интерфейсе пока отсутствует; эти таблицы можно редактировать SQLite-инструментами при остановленном сервере. Список уведомлений и задачи пока не подключены к виджетам интерфейса.

Настройки также сохраняются в браузере как запасная копия. При запуске настройки из SQLite имеют приоритет.

## Резервная копия и перенос

- Нажмите **БАЗА → Скачать резервную копию**. Скачается согласованный снимок `tracktor-backup.sqlite3`, даже если приложение работает.
- Для восстановления остановите сервер, сохраните текущую базу отдельно и замените `data/tracktor.sqlite3` резервной копией, переименовав её в `tracktor.sqlite3`. Затем запустите BAT.
- Для переноса на другой компьютер скопируйте папку проекта вместе с `data` и установите там Python.
- При обновлении файлов проекта сохраняйте свою папку `data`. Она исключена из Git и не должна попадать в публичный репозиторий.

В существующей конфигурации Supabase URL и ключ были пустыми; перенос данных из ранее подключённого облачного проекта не выполняется.

## Подключение Cloud.ru Foundation Models

Интеграция использует официальный OpenAI-совместимый API: `https://foundation-models.api.cloud.ru/v1`, методы `GET /models` и `POST /chat/completions`, авторизацию `Authorization: Bearer <Key Secret>`. Дополнительные Python-пакеты устанавливать не нужно.

1. Запустите BAT. Нажмите **CLOUD.RU** в шапке (**AI** на телефоне) или **БАЗА → Подключить Cloud.ru**.
2. Вставьте **Key Secret** с доступом к сервису **Foundation Models** и нажмите **Сохранить ключ**. Key ID вместо секрета не подходит. Подробнее — [аутентификация Cloud.ru](https://cloud.ru/docs/foundation-models/ug/topics/api-ref__authentication).
3. Приложение загрузит актуальный каталог. В выборе отображаются текстовые модели с поддержкой chat completions; специализированные OCR, guard, аудио, embeddings и rerank отфильтрованы. Названия не зашиты в программу. Список можно обновить вручную. Под моделью показываются доступные сведения о контексте, рассуждениях и внешнем провайдере.
4. Выберите модель и нажмите **Сохранить модель**. Ключ и модель сохранятся после перезапуска и переноса базы.
5. Выберите лимит проверки: **128** токенов по умолчанию, **512** или **1024** для моделей с рассуждениями. Нажмите **Подключить и проверить**. Приложение сохранит выбор и отправит модели короткий запрос «Ответь одним словом: работает.». **Это расходует токены по условиям вашего Cloud.ru.** Ответ появится в окне; увеличенный лимит может увеличить расход.

Один только каталог не подтверждает ключ: Cloud.ru может отдавать его публично. Успешной проверкой считается полученный итоговый текст выбранной модели. Если лимит закончился на рассуждениях и текста нет, приложение сообщает об этом без зелёного статуса. В интерфейсе показывается дата **последней** проверки; действительность ключа не проверяется платными запросами в фоне.

Проверка подключения выполняется по одной: повторное нажатие, перезагрузка или закрытие вкладки не создают второй одновременный проверочный запрос. После ошибки сети, тайм-аута, 429 или 5xx автоматической повторной генерации нет. Используется документированный `max_completion_tokens`; переход на старый `max_tokens` возможен только после явного отказа API принять именно этот параметр, максимум один раз.

Ключ хранится **без шифрования в локальной SQLite-базе**, в отдельной таблице. Он входит в резервные копии и переносится вместе с `data`: храните такие файлы как содержащие секрет. После сохранения API возвращает только признак наличия ключа, модель и дату проверки. Сохранённый ключ не выдаётся браузеру, не помещается в localStorage/sessionStorage и не используется в URL. HTTPS-запросы выполняет локальный Python-сервер только к официальному адресу; перенаправления заблокированы.

**Удалить ключ** очищает сохранённые данные подключения в приложении. Это не отзывает ключ в личном кабинете Cloud.ru и не удаляет его из ранее скачанных резервных копий. Для замены вставьте новый Key Secret и сохраните его.

Ошибки ключа/прав, квот, баланса, контекста модели, DNS, TLS и прокси отображаются с отдельными подсказками в окне Cloud.ru. Для ключа проверьте правильный проект, доступ к Foundation Models, срок действия, разрешённые IP и временные ограничения; для сети — исходящий HTTPS к `foundation-models.api.cloud.ru:443`. Проверка сертификатов не отключается. Недоступность облака не отключает локальную базу. Обновление старой базы до версии схемы 3 выполняется автоматически без повторного заполнения демонстрационными данными и без удаления пользовательских навыков/настроек. Подробности исследования и границы проверок — [CLOUD_RU_AUDIT.md](CLOUD_RU_AUDIT.md).

После настройки модели можно запускать навыки кнопкой ▶ в командном центре. Официальный пример работы — [быстрый старт Foundation Models](https://cloud.ru/docs/foundation-models/ug/topics/quickstart).

## Настоящий запуск навыков

1. В командном центре нажмите **▶** на карточке навыка.
2. Прочитайте его инструкцию, введите задачу и исходные данные.
3. Проверьте выбранную модель Cloud.ru и задайте лимит ответа: 1024, 2048 (по умолчанию), 4096 или 8192 токена.
4. Нажмите **Выполнить навык**. Инструкция навыка и введённая задача отправятся модели через сохранённый Key Secret; запуск расходует токены Cloud.ru.
5. Получите текстовый результат. Его можно скопировать или скачать в **TXT с UTF-8 BOM** для корректного открытия русского текста в Windows.

Четыре встроенных навыка получили явные текстовые инструкции: анализ рекламного аккаунта, отчёт в три шага, сводка кампаний и цикл рекламных креативов. Это шаблоны этого приложения, составленные по назначению карточек. Для пользовательского навыка используется инструкция, введённая при его создании; она показывается перед запуском. Если описание пустое, модель получает название навыка и вашу задачу.

Задачи, использованная модель и результаты сохраняются в локальной базе и входят в её резервные копии. При повторном открытии карточки показывается последний запуск. Закрытие окна навыка или перезагрузка страницы не отменяет уже принятый запрос: сервер продолжает выполнение, а повторное открытие показывает его состояние. **Окно BAT оставьте открытым.**

Одновременно выполняется один навык. Повторная отправка того же идентификатора возвращает существующий запуск, включая уже завершённый, без нового запроса к модели. После потери HTTP-ответа интерфейс сначала ищет принятый запуск. Кнопка **Запустить ещё раз** создаёт новую задачу и расходует токены заново.

Если остановить сервер до сохранения результата, следующий запуск BAT пометит задание как прерванное. Запрос мог быть обработан в облаке; автоматической повторной отправки нет. Пустой ответ после исчерпания лимита рассуждений отмечается ошибкой с предложением увеличить лимит. Частичный ответ сохраняется с отметкой об ограничении токенов.

Навык формирует текст: анализ, рекомендации, отчёт или материалы по брифу. Изменение рекламных аккаунтов, публикация, отправка сообщений и выполнение команд требуют отдельного подключения инструментов. Каждый запуск получает отдельную задачу; чат с историей диалога здесь не добавляется.

## Интерфейс

- Командный центр: клиенты, карта, календарь, команда, навыки и процессы.
- «Второй мозг»: кольца, круг, соты и силовая раскладка; поиск, темы, фильтры, перемещение и масштабирование; экспорт PNG.
- `+` / `-` — масштаб, `0` — центрирование, `/` — поиск, `Esc` — закрытие карточки, `?` — справка.
- Адаптивная версия для телефона и компьютера.

AI-навыки выполняют текстовые задачи через Cloud.ru. Расписание процессов пока демонстрационное; для внешней автоматизации нужен отдельный исполнитель. Файлы карты, команда, воронка и часть виджетов остаются демонстрационными. Подробности исходной реконструкции — в [VIDEO_AUDIT_RU.md](VIDEO_AUDIT_RU.md).

## Проверки

Для приложения нужны только Python и современный браузер. Node.js и Playwright используются исключительно в тестах.

```bash
python3 -m unittest discover -s tests -p 'test_*.py' -v
node --check app.js
node --check database.js
node --check cloud.js
node --check skills.js
node tests/smoke.mjs
```

Браузерные проверки на ширинах 390, 740, 1024 и 1440 пикселей:

```bash
npm install --no-save playwright
npx playwright install chromium
node tests/visual.cjs
node tests/cloud-ui.cjs
```

На Windows дополнительно запускается `tests/windows-launcher.ps1` через Windows PowerShell 5.1: настоящий BAT проверяется в папке с кириллицей и спецсимволами, с занятым портом и повторным запуском. В одноразовом CI-окружении также проверяются скачивание подписанного установщика с python.org и установка Python для текущего пользователя.

Тесты запускают сервер с отдельной временной базой и не затрагивают `data/tracktor.sqlite3`. Проверяются сохранение после перезапуска, резервное копирование, валидация запросов, интерфейс и добавление навыка без регистрации. Cloud.ru-тесты используют только вымышленные ключи и имитированный провайдер: проверяются миграция базы, сохранение/удаление ключа, выбор модели, проверка, ошибки авторизации/интернета и отсутствие утечки секрета. Проверки навыков также используют имитацию провайдера: проверяются встроенные/пользовательские инструкции, выбранная модель, защита от повторной оплаты, частичные и ошибочные ответы, восстановление после остановки сервера, повторное открытие окна и TXT с русским текстом. Они не отправляют запросы реальным моделям и не расходуют токены. Снимки сохраняются в `artifacts/screenshots`.

## Структура

- `Aspksa.bat`, `Start-Tracktor.ps1` — запуск на Windows, поиск и установка Python.
- `server.py` — HTTP-сервер и SQLite API на стандартной библиотеке Python.
- `sqlite-schema.sql`, `seed-data.json` — создание новой базы и начальные примеры.
- `database.js` — браузерный клиент локального API.
- `cloudru.py`, `cloud.js` — серверный клиент Foundation Models и окно настройки Cloud.ru.
- `skillrunner.py`, `skills.js` — выполнение навыков, сохранение запусков и показ результатов.
- `index.html`, `styles.css`, `app.js` — интерфейс и карты SVG.

Локальному API нужен работающий Python-сервер. GitHub Pages не запускает Python и не предоставляет доступ к вашей SQLite-базе; workflow проекта выполняет проверки без публикации локальной версии.
